## 2. 游戏定位

第一人称3D观察解谜游戏。玩家以发条玩具的身份，穿过爷爷的书房、妈妈的卧室和自己的儿童房，通过换位置观察、转身和操作少量物件，逐步拼回一个家庭的记忆。

- 叙事主线：三代人、同一栋房子、同一棵树、一首摇篮曲。
- 情绪：好奇 → 专注 → 惊叹与回家；保持温暖。
- 时间表现：三段记忆以同一场逐渐入夜的黄昏串联，这是跨年代的记忆呈现，不解释为三代人在同一个物理日期生活。
- 照片卡作为记忆的表现形式，不声称1930年代角色当时使用了拍立得。
- 当前技术栈由用户明确指定：**Lux3D + Blender + Unity**。
- Unity版本、渲染管线、目标平台及设备尚未确定；原先的桌面网页发布方案不能直接当作Unity方案。

### 实现现状

仓库目前仍是Vite/TypeScript/Three.js早期原型，未迁移Unity。src/main.ts仍存在房间旋转、第三人称切换和旧的门朝向通关逻辑；src/preview.ts是程序化布景预览，不是三关完整可玩版本。

已产出：三关欧式概念图、多视角参考板、Lux3D候选资产标注和分工文档。

尚未完成：Unity工程、三关新规则灰盒、Lux3D实际样件、最终模型、完整交互和光学验证。

## 4. 共同操作与世界规则

沿用最新讨论方向：
- 第一人称探索，WASD移动，左右键人物原地转身90°，E交互。
- 鼠标小幅环视；原文±60°/±45°为调参候选，舒适度与可读性需实测。
- 房间、重力和固定光源不会因人物转身而改变。
- 移动改变观察位置，不会让原本不存在的光路突然接通。
- 家具只有在明确交互时移动：床、衣柜、抽屉、盒盖和娃娃屋转盘等。
- 转盘操作时，方向键究竟切换为转盘控制、以及操作后是否自动退出，需要在灰盒统一交互规则。
- 第三关灯绳引发昼夜切换是明确的童话/记忆机关，与普通转身区分。
- 展示用全景、记忆馆或结尾镜头不等于新增可玩第三人称模式。
- 重置、提示与存档的具体规则属于后续实现规格，不能沿用相互矛盾的旧描述。

## 5. 第一关：书房「四扇门」

**用户明确决定：保留四扇门，不改成书柜四个机关格。**

### 当前路线

记忆照片提示太阳门 → 走到四门前，通过气窗看走廊镜中的外侧符号 → 辨认太阳门 → 从适当位置读夕阳照到的书脊 → 操作留声机得到小钥匙 → 打开书桌抽屉得到出口钥匙与老照片 → 打开太阳门离开。

- 东墙四门外观相似，内侧没有直接显示的符号。
- 门外牌按图中候选排布为月、星、日、钥；从北向南第三门为太阳。顺序是当前布景方案，不能仅凭生成图默认坐标。
- 四扇门连接同一条走廊；太阳门可解锁，其余门保持锁闭。
- 走廊对面高位镜与各门气窗构成观察关系。
- 书脊线索暂沿用“日入门，可归”，使用准确文字贴图。
- 留声机藏钥匙的机关外观已画出，具体是喇叭转动、检修盖或联动开口，需定为同一套可实现动作，不混用三种表现。

### 书柜制作结论

**Blender柜体 + 可选Lux3D冠部雕饰 + 独立谜题书脊 + Unity光照表现。**

左右两组柜体分列壁炉两侧。规则层板、下柜、背板和柜门直接Blender；先制作一组模块再复制调整。普通书本少量变体复用；谜题书本独立排布、独立贴图。浅浮雕可直接曲线/叶片制作，S07不是必须生成。

### 验证门槛

1. 在实际眼高和抬头范围内，真的能从气窗看到对应门的外侧牌。
2. 镜面是否把四个符号同时全部暴露，能否保留逐位置观察的意义。
3. 第三扇门开合与走廊通行不冲突。
4. 书脊可读但不过分显眼；观察角度差异有视觉依据，不只用朝向数值强制显隐。
5. 钥匙链是否造成过多重复找物；先试玩，再决定是否简化。

## 6. 第二关：卧室「镜中的秘密」

本节名称用于描述内容；旧名“三把锁”是否保留，尚未正式定稿。

### 当前讨论路线

床底光斑照片 → 解除床头短链 → 观察固定西窗光、衣柜镜门与床底的关系 → 推床取出铁皮盒 → 得到钥匙、玻璃弹珠和日期纸片 → 发现“柜子后面”的提示 → 读镜中三符号并输入衣柜符号盘 → 移开衣柜 → 用钥匙开隐藏门离开。

可选情感线索：录音机播放同一首摇篮曲。

### 锁的含义

“床的链条锁、衣柜符号锁、暗门钥匙锁”是此前提出的澄清建议。旧文档把发现光路称作额外光敏锁，与静态观察规则冲突，不直接沿用。

床底的光和盒子应有实际空间依据；看向衣柜只会改变可见性，不应该创造光或盒子。

### 制作重点

- Blender建立衣柜箱体、两扇门、铰链、镜面、滑轨与暗门；Lux3D仅作外观雕饰。
- 真实移动的床、脚轮、短链、锁扣与铁皮盒内腔/盒盖需拆开。
- 普通五斗橱/床头柜直接搭箱体，避免无意义的AI整件生成。
- 参考图衣柜分扇不清，不能直接照图拆件。
- 可动床和柜体不要把角色挤出边界；行程先用灰盒验证。

### 尚未闭合的问题

1. 三符号的实体来源在哪里，如何被镜子映出，玩家为什么知道顺序。
2. 光路是物理镜面效果还是受控的预设表现，画面与判定如何一致。
3. 衣柜移动距离、暗门露出宽度与缝纫机位置。
4. 是否要求先关闭镜门再移动柜体。此项是制作建议，尚未确认。

## 7. 第三关：儿童房「房间里的房间」

### 当前讨论路线

观察大房间与娃娃屋对应 → 从小窗/屋顶星图读“太阳 → 月亮 → 回家” → 绕桌找到把手，转动娃娃屋接住夕阳 → 小灯点亮并锁存 → 拉墙边灯绳进入夜晚 → 再绕桌转动娃娃屋，令小镜面接住月光 → 大灯点亮并锁存 → 两盏灯齐亮，解除出口机关 → 走出并揭示大房间也是娃娃屋。

可选秘密：娃娃屋暗抽屉中的小照片，暗示玩家也是家中记忆的一部分。

### 当前制作建议

- **娃娃屋壳、窗洞、屋顶、转盘、定位与把手用Blender。**
- 内部家具从大房间已完成模型缩放、简化后复用，不另让AI猜布局。
- 把手随转盘而转，固定底座和桌子不转；四侧可绕行。
- 小星灯与大星灯独立控制，普通床头灯不是谜题星灯。
- 建议小灯未亮前不推进到夜晚，防止丢失夕阳造成软锁；最终交互反馈待设计。
- 出口从木板封门的概念发展为带黄铜端件的可动木闩，是当前视觉候选；运动方向与门锁逻辑待验证。
- 屋顶星图和开放正面用于概念展示。若光学谜题需要封闭与遮挡，正式模型必须补充壳体/挡板。

### 场景状态

| 状态 | 小灯 | 大灯 | 昼夜 | 出口 |
|---|---|---|---|---|
| 起始 | 灭 | 灭 | 黄昏 | 锁闭 |
| 当前主概念图 | 亮并锁存 | 灭 | 黄昏 | 锁闭，一亮一暗指示 |
| 入夜继续解谜 | 保持亮 | 灭 | 夜晚 | 锁闭 |
| 完成 | 亮 | 亮 | 夜晚 | 木闩解除，可开门 |

图中灯罩受夕阳变暖，不代表大灯已经发光。不同状态不要在同一主视图混用。

### 验证门槛

小窗方位映射、日夜各档角度、镜面与大灯路径、图案观察角度、转盘把手可达性、桌子四侧净空，以及日夜操作不会产生死局。

## 10. 开发顺序与阶段验收

以下是制作建议，不是已承诺排期：

1. **统一尺度与Unity起步**：选Unity版本/渲染管线/发布平台，定角色眼高、门高、移动与转身参数；导入一个简单FBX核对尺度、朝向和材质。
2. **第一关完整灰盒**：四门、气窗镜面、书脊、留声机、抽屉到通关；验证实际视线和交互。先使用基础网格。
3. **第一批Lux3D样件**：建议椅子和兔子验证外观链路；留声机验证复杂外观与手工结构组合。记录实际清理成本。
4. **第一关美术垂直切片**：做完柜体与谜题书、留声机、书桌、门与光照，让一关完整可玩并能体现最终美术。
5. **第二、三关灰盒**：闭合符号来源、滑柜、转盘和日夜规则，再生产剩余模型；第二、三关技术验证也可在第一关精修前小范围开展。
6. **资产替换与统一打磨**：共享材质、灯具、五金，补音频、提示、存档，测试关键状态与性能。
7. **展示与参赛材料**：保留输入图、生成结果、Blender整理、Unity实际运行对照；最后制作视频和报告。赛事日期和要求以当前官方页面核验，不沿用旧文档的“剩余天数”。

第一关切片通过的最低条件：可以从进屋到离开完整走通；镜中信息可读；钥匙能拿取；抽屉有内腔；门不穿模；场景与当前美术方向一致；陌生玩家能理解观察关系。未通过前不把全套概念图等同于开发完成。

## 11. 下一步最重要的工作

**先确定第一关的统一平面和眼高，用Blender/Unity验证四门镜面，再制作书柜主体与谜题书脊。**

待定项集中为：
- Unity版本、渲染管线、目标设备/平台。
- 三关实际尺寸、角色比例及镜面观察站位。
- 第二关三符号来源和三锁定义。
- 第三关日/月光路、转盘角度和提前拉绳规则。
- 首批Lux3D样件及生成预算。

本轮整理不修改运行时代码，不创建Unity工程，不调用付费生成，不自动提交Git。后续实现以实际验证补齐上述问题，再展开细化规格。
