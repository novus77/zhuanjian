## 0. 一句话

**你是一个发条小人，在一间老房子里醒来。你用第一人称在房间里探索；按 ← → 让自己左右转 90°——世界在眼里转过一整个方向，但房间本身不动。你要靠观察、靠换个方向看，把三间房里的秘密找出来，才能回家。**

类型：第一人称 3D 观察解谜
平台：桌面浏览器（Chrome / Edge，WebGL2）
关卡：3 关
单关时长：3–10 分钟
总时长：20–25 分钟
团队规模：3 人（开发 / 策划 / 美工）

## 1. 项目背景与目标

### 1.1 比赛信息

- 赛事：群核科技 Aholo 全球 3D AI 黑客松
- 主题：Play in 3D, Create with Aholo
- 截止：2026-11-19 19:00（北京时间），当前剩余 17 天
- 参赛要求：必须使用 Aholo Lux3D，并让它参与核心 3D 内容或关键创作流程
- 评审权重：
  - 群核技术栈应用 30%
  - 作品有趣程度 25%
  - 创新性 20%
  - 完成度 20%
  - 传播 5%

### 1.2 项目目标

1. 做一款**完整可玩**的 3 关网页 3D 解谜游戏，而不是一个漫游 demo。
2. 让 **Aholo 的生成能力成为玩法本身**：房间由 SpatialGen 生成，关键道具由 Lux3D 生成，第三关的娃娃屋由 Lux3D 从房间照片直接生成。
3. 用“转身换一个方向看”这一个动作，串起三种后果：通路、视角、光线。
4. 用一个温暖的 Happy Ending 收尾，让观众在 30 秒预告片里记住这个游戏。

### 1.3 成功标准

- 陌生玩家不看说明，3 分钟内能理解“转房间”的规则。
- 三关都能在 10 分钟内通关，且每关至少有一个“啊哈”瞬间。
- 评委能在项目报告中清楚看到 Aholo 技术栈的完整使用链路：prompt → 生成 → 进入游戏。
- 提交物包含：项目报告书、可玩 Demo 链接、30 秒演示视频、源代码、小红书发布链接。

## 2. 设计目标 / 非目标 / 反目标

### 2.1 设计目标

- **一个核心动词**：所有关卡都围绕“转身 90°，换一个方向看”展开，不新增第二套操作。
- **观察即解谜**：谜题的核心是“看到并理解空间关系”，不是找隐藏物品或拼手速。
- **转身即换视角**：每一次转身都让你看到刚才看不到的那一面，让玩家注意到 Aholo 生成的房间细节。
- **短而完整**：3 关、20–25 分钟、有开头有结尾，完成度优先于内容量。
- **温暖的情绪**：微缩模型、旧木头、黄铜、八音盒；结尾明确团圆。

### 2.2 非目标

- 不做开放世界、不做多人联机、不做关卡编辑器。
- 不做移动端适配（桌面浏览器优先）。
- 不做中英双语（游戏内中文；预告片配英文字幕）。
- 不做复杂战斗、跳跃平台、计时挑战。
- 不做需要读大量文本的叙事。
- 不做上下（X/Z 轴）旋转；不做连续自由旋转。
- 不做第三人称视角，不做上下翻转旋转。

### 2.3 反目标（出现这些说明方向错了）

- 变成一个“生成一个房间然后自由漫游”的技术 demo。
- 玩家大部分时间在找钥匙/找按钮，而不是在理解空间。
- 连续自由旋转导致 3D 眩晕。
- 三关是三套不同玩法，玩家每关都要重新学。
- 结尾让人感到“被关在娃娃屋里”的恐怖/压抑，而不是温暖。

## 3. 设计支柱

1. **一个动作，三种后果**：转身——看到原本在身后的东西、换一个方向看光、发现门的新位置。
2. **观察是最高级的操作**：玩家先看懂，再动手；不是先动手，再看懂。
3. **每次转身都是一次重新发现**：新的一面墙、新的光、新的线索。
5. **温暖的故事，明确的结局**：三间房、三代人、一首摇篮曲。

## 4. 世界观与叙事

### 4.1 设定

一栋老房子“记性坏了”。它把每个房间都转到了错误的角度，家具掉在地上，门也找不到了。每间房入口都有一张拍立得——那是房间“记得的样子”。玩家要做的不是修家具，而是把房间转回照片里的角度。

三间房 = 三个年代 = 同一个家庭的三段记忆：

- 书房：爷爷的年代
- 卧室：妈妈的年代
- 儿童房：玩家的年代

最终揭示：这栋房子本身也是一个微缩模型，摆在一间温暖客厅的书架上。长大后的孩子回到老屋，给娃娃屋上发条——玩家不是被困住，而是这个家被记住的一部分。

### 4.2 叙事结构

| 幕 | 场景 | 情绪 | 信息释放 |
|---|---|---|---|
| 序章 | 书房地板 | 迷茫 → 好奇 | 纸条告诉玩家“房子把房间转乱了” |
| 第 1 关 | 爷爷的书房 | 温暖、怀旧 | 照片背面第一次出现“爷爷” |
| 第 2 关 | 妈妈的卧室 | 温柔、略带伤感 | 八音盒旋律 + 妈妈小时候的秘密 |
| 第 3 关 | 儿童房 | 明亮、期待 | 照片里多出的影子 = 拍照的人 |
| 结尾 | 客厅书架 | 团圆、释然 | 长大后的孩子回来上发条 |

### 4.3 完整叙事脚本

全片文本量控制在 300 字以内，无配音；靠纸条、照片、环境音、八音盒。

## 5. 核心玩法

### 5.1 房间模型

- 每关一个**矩形房间**，尺寸放大到接近真实住宅（书房 9.6×6.4×4.6 m，卧室 9.0×6.0×4.4 m，儿童房 10.4×7.0×4.8 m）。
- 六面均为墙/地板/天花板；第一人称相机位于房间内部，不需要剖切墙。
- 房间里有三类物体：
  - **固定物（fixed）**：书架、镜子、窗、吊灯、门框——跟着房间一起转。
  - **机关物（mechanism）**：钥匙、照片、转盘、密码盘、门扇、光敏板——可以拿取、放置、触发。
  - **装饰物（decor）**：书堆、相框、玩具、地毯——只做氛围，不参与旋转物理。
- 房间悬浮在一个“虚空舞台”上，外部有固定光源（太阳/月光）和固定走廊/架子。
- **世界是静止的**：房间、家具、光都不动。玩家转身之后，看到的是同一间房的另一面。

**尺寸基准（1 游戏单位 = 1 米）**：

| 对象 | 尺寸/参数 |
|---|---|
| 第 1 关书房 | 9.6×6.4×4.6 m |
| 第 2 关卧室 | 9.0×6.0×4.4 m |
| 第 3 关儿童房 | 10.4×7.0×4.8 m |
| 发条小人 | 1.6 m 高（可直接用第一人称视角，不再是小矮人） |
| 床 | 0.6 m 高 |
| 书桌 | 0.9 m 高 |
| 衣柜 | 2.2 m 高 |
| 娃娃屋（第 3 关） | 0.8 m 高 |
| 第一人称相机 | FOV 72°，眼睛高度 1.4 m |
| 移动速度 | 2.4 m/s |
| 自动跨步 | ≤0.15 m |
| 攀爬范围 | 0.15–2.5 m（走到边缘按 E） |

### 5.2 旋转规则（旋转的是人，不是房间）

**核心设定：房间是固定的，转的是玩家人物的朝向。**

- 按 **← / →**，发条小人原地**转身 90°**（共 4 个朝向：正前 / 右 / 后 / 左）。
- 转身是**离散的 90° snap**，带 0.45 秒的转身动画和轻微视点上升，不做连续自由旋转。
- **房间、家具、光、重力都完全不变**。玩家转身后看到的是房间的另一个方向。
- 为什么这样设计：
  - 世界是真实的，只有玩家的"注意力"在转——更符合"观察解谜"而不是"魔法机关"。
  - 物理完全稳定，不会穿模、不会有家具掉落、不会有眩晕。
  - 仍然保留"换个角度看世界"的核心体验。
- 转身时，画面会有一小段缓和过渡（0.45s 内视角旋转 + 轻微 FOV 呼吸），避免瞬移感。
- 允许按 R 重置到初始朝向。

**关于"门与光"的谜题机制**：

- 门的位置固定，但**只有某些角度能看清门框上的刻字**（比如斜光扫过才反光）。
- 光的角度固定，但**站在不同方位看到的光斑位置不同**。
- 所以谜题从"把门转过去"变成"**走到对的位置、转到对的角度，才看得见**"。

### 5.3 重力与物体

- 重力方向永远是世界向下，**没有任何东西会因为玩家转身而移动**。
- 家具、道具都固定在地板上；房间是完全静态的真实空间。
- 只有玩家（发条小人）会移动和转身。
- 不做真实物理模拟，也不需要任何物体状态表——只有"玩家位置 + 玩家朝向 + 机关 flags"。

### 5.4 门、光、锁

- **门**：只有和外部通道对齐的门才能打开；其他门是假的/锁死的。
- **光**：外部固定光源（太阳/月光）；窗户转到哪，光就照到哪面墙。光可以照亮符号、触发光敏锁、点亮灯。
- **光线是状态驱动的**：光束是否接通由房间朝向 + 娃娃屋转盘角度等条件决定，不做真实光学模拟；光路用可视化光束表示。
- **锁**：三类——
  - 物理锁（钥匙、链条、门闩）
  - 知识锁（符号密码、图案顺序、视角观察）
  - 光线锁（把窗转到光源方向，让光打到光敏板上）
- 每关至少有一个物理锁 + 一个知识锁，第三关加入光线锁。

### 5.5 状态机数据结构

**核心约定**：

- 房间完全静态，不存在"朝向状态表"。
- 游戏状态只有三样：**玩家位置（x,z）、玩家朝向（0/90/180/270）、机关 flags**。
- 机关 flags 是全局的（`chainPulled`、`lockA`、`lockB`、`lockC` 等），不随玩家转身重置。
- 重置（R）恢复"起点位置 + 初始朝向 + flags 初始值"。

示例：

```json
{
  "id": "level_01_study",
  "room": { "width": 9.6, "depth": 6.4, "height": 4.6 },
  "player": { "start": [-3.2, 1.4], "facing": 90 },
  "objects": {
    "bookshelf": { "position": [-1.0, 0, -3.0], "type": "fixed" },
    "desk": { "position": [1.0, 0, 1.3], "type": "fixed" },
    "gramophone": { "position": [-3.9, 0, 2.2], "type": "mechanism" }
  },
  "flags": { "drawerUnlocked": false, "sunDoorOpen": false },
  "triggers": [
    { "type": "inspect", "object": "bookshelf", "requireFacing": 0, "requireLight": true, "flag": "readBookSpines" }
  ]
}
```

> 说明：谜题的"必须在某个角度才看得见"用 `requireFacing` 表达，不需要任何旋转状态机。

### 5.6 操作

| 操作 | 键位 | 说明 |
|---|---|---|
| 移动 | WASD | 相对当前朝向移动 |
| **转身 90°** | **← / →** | 发条小人原地转身，共 4 个朝向 |
| 环视 | 鼠标移动（点击画面锁定指针） | 小幅自由看，看不到身后，必须转身 |
| 交互 | E / 点击高亮物 | 拿取、放置、开门、读照片 |
| 重置 | R | 回到初始位置和朝向 |
| 释放鼠标 | Esc | 解除指针锁定 |

> 鼠标环视是"转头"（左右各约 60°，抬头低头各约 45°），**看不到正后方**——想看身后必须按 ← → 转身。这个限制是谜题的基础。

### 5.7 相机（第一人称）

- 第一人称，相机位于发条小人眼睛高度 1.4 m，FOV 72°，屏幕中央有准星。
- 鼠标移动 = 转头（yaw 限制在 ±60°，pitch ±45°），**不能直接看到身后**。
- 按 ← → 是整个人转身 90°，转身时相机与人物一起转。
- 转身动画 0.45 秒，相机有轻微侧倾和视点高度起伏，避免生硬。
- 没有第三人称模式。
- 舒适选项：可关闭转身时的视角侧倾、可关闭头部晃动。

### 5.8 角色移动与攀爬

- 第一人称下角色模型不可见，只保留碰撞体。
- 角色在房间地板上行走；自动跨越 ≤0.15 米的台阶/门槛。
- 高于 0.15 米的家具（床、衣柜、箱子）需要走到边缘按 E 攀爬。
- 不做跳跃、不做坠落伤害。
- 角色不会掉出房间边界（房间是封闭的）。

### 5.9 密码输入 UI

- 第 2 关的符号盘是一个 3 槽转盘：点击槽位切换太阳/月亮/星星，三个槽位都填好后按“确认”。
- 输入错误时符号盘轻微回弹，播放不刺耳的卡住声；不扣血、不重置。
- 已见过的符号会记录在界面右上角的“笔记本”里，玩家不需要背。
- 密码正确后，锁 B 播放齿轮咬合 + 八音盒上行三音。

### 5.10 存档与进度

- 使用 `localStorage` 保存：已通关关卡、已解锁记忆馆、已收集秘密、音量设置。
- 每关开始时自动存档；不需要手动保存。
- 提供“重新开始本关”和“从第一关开始”两个选项。

### 5.11 关卡切换与叙事节奏

- 玩家走出门后，画面淡出到黑，播放 2 秒环境音；淡入下一关。
- 每关开始前，拍立得从门缝滑入，玩家必须拿起照片（或 3 秒后自动拿起）才能开始解谜。
- 每关结束后，照片显影并钉到“记忆板”；记忆板是关卡选择界面。
- 第三关结束后直接进入结尾演出，不再回到记忆板。

### 5.12 结尾演出方案

- 结尾采用 **15 秒预渲染短片 + 游戏内最后 3 秒拉远** 的混合方案：
  - 游戏内：角色走出门后，房间被强制归一到“直立、Y=90°”的展示朝向，锁定输入，镜头从娃娃屋内部拉远到书架，画面渐暗。
  - 预渲染：客厅、壁炉、雪窗、成年女性、巨型发条钥匙等镜头，用 LuxReal / AI 视频 / 简单 3D 预渲染制作，作为视频播放。
- 序章为**引擎内实时演出**（房间 + 纸条 + 钥匙特写），不需要新增角色。
- 不做实时人物动画，不新增可玩场景。
- 预渲染短片在 Day 12–15 制作，作为 M5 的必交素材之一。


### 5.13 通关判定

- **第 1 关**：太阳门在 N 方向、用钥匙开门后，角色走出门触发通关。
- **第 2 关**：三把锁全部打开后，掀开活板门并落入下层小房间触发通关。
- **第 3 关**：两盏星星灯都亮起后，房间强制归一到“直立、Y=90°”的展示朝向，封死的门打开，角色走出门触发结尾演出。
- 通关判定不依赖“是否拿齐秘密”，秘密只影响收集度。




### 5.14 失败、重置与提示

- **没有死亡、没有计时、没有失败结算**。
- 软重置：10 秒无操作且当前状态疑似卡住时，提示“要重置这间房吗？”。
- 三档提示：
  - 90 秒后：一句方向提示。
  - 再 90 秒后：高亮相关物件。
  - 再 90 秒后：演示走到正确位置并转身。
- 提示不收费、不扣分，只记录“是否使用过提示”，用于通关评价。

## 6. 反馈与音频设计

### 6.1 四层反馈

| 层级 | 内容 | 作用 |
|---|---|---|
| 一级：转身本身 | 0.45 秒转身、发条短促上弦、布料摩擦、轻微侧倾 | 让“转”有身体感 |
| 二级：世界变化 | **没有变化**——世界不动。变化的是你看到的那一面 | 强化「我只是换了个方向看」 |
| 三级：状态确认 | 朝向小罗盘（东南西北）、照片卡 | 让玩家知道自己在哪、面朝哪 |
| 四级：叙事反馈 | 照片背面字迹、八音盒旋律、环境音变化 | 让“转”有意义 |

### 6.2 转身演出（轻量三段）

| 阶段 | 时间 | 画面 | 声音 |
|---|---|---|---|
| 起身 | 0–0.08s | 视角轻微上升 2cm | 发条上弦一声短「咔」 |
| 转身 | 0.08–0.4s | 视角水平扫过 90°，边缘轻微运动模糊；世界纹丝不动 | 布料摩擦 + 齿轮短促转动 |
| 落定 | 0.4–0.45s | 视线稳住，朝向罗盘指到新方向 | 轻微「哒」，脚掌落地 |

**关键**：转身不做夸张演出——它不是「世界转动」，而是「转头看」。玩家应该觉得房间完全没变，只是自己的注意力换了方向。这是本作和《纪念碑谷》类旋转房间游戏最重要的区别。

### 6.4 音乐系统

**同一首摇篮曲，三种编制：**

- 第 1 关（爷爷）：八音盒 + 老钟摆，旋律简单、温暖。
- 第 2 关（妈妈）：钢琴 + 风声，同一个旋律，更柔和。
- 第 3 关（孩子）：风铃 + 雨声，同一个旋律，更清澈。
- 结尾：三层同时奏响，加弦乐——三代人的记忆合在一起。

实现要点：

- 每关的音乐分 3 个 stem：旋律、和声、环境。
- 转身时，旋律 stem 升一个音；转到正确朝向时，和声 stem 加入。
- 解开谜题时，音乐短暂停顿（0.2s）再解决，制造呼吸感。
- 结尾用同一旋律的完整合奏。

**音乐制作默认方案（无作曲家时）**：

- 用 MIDI/DAW 制作一首 8–12 小节的摇篮曲，导出 3 个独立 stem（旋律/和声/环境）。
- 音色用音乐盒、钢琴、风铃的采样或合成器；不追求真实演奏。
- 音效使用 CC0 素材库 + Web Audio 合成（齿轮、木头、金属）。
- 若有团队成员会乐器/编曲，优先真人演奏，情绪更好。

### 6.5 记忆馆与拍照

- 每关通关后解锁“记忆馆”：房间变成纯展示台，无重力、无谜题，鼠标 360° 自由旋转、滚轮缩放。
- 旁边标注资产来源：`书房 · SpatialGen` / `胡桃木书架 · Lux3D` / `黄铜钥匙 · Lux3D`。
- 玩家可以拍一张拍立得，存进“记忆板”。
- 记忆馆复用同一套模型，成本低，但能让评委认真看一遍 3D 资产。
- 拍照模式为可选项，时间不够可砍。

## 7. 关卡设计

### 7.1 设计原则

1. **一关一个动词**：第 1 关“转”，第 2 关“落”，第 3 关“套”。
2. **一关两个锁**：一个物理锁 + 一个知识锁。
3. **一关一个 twist**：改变玩家对房间的理解。
4. **一关一个可选秘密**：给二周目和直播留内容。
5. **任何状态都可解**：不设死局；10 秒无操作出现软重置提示。
6. **线索前置**：玩家需要的信息必须在需要它之前可见/可听。
7. **每关最多 5–7 个可交互物**：不堆机关。

### 7.2 第 1 关：书房「四扇门」

**目标**：找到真门，离开书房。

**房间**：9.6×6.4×4.6 m。四扇门在东墙并排（月亮 / 星星 / 太阳 / 钥匙），西墙偏北一扇雕花木窗，夕阳从窗口斜射进来，走廊在东墙外。

**核心机制：门的外侧符号只有转身才看得见**

- 四扇门的门楣上各刻一个符号，但**只刻在门的外侧（走廊那一面）**。
- 门上方有一个小气窗，从气窗能瞥见走廊里的一面黄铜镜——**镜子里映出的是"面朝走廊那扇门"的外侧符号**。
- 但气窗在门的正上方，**只有正对着东墙站着（朝东），才看得见镜子**；背对、侧对都看不到。
- 所以玩家必须：**走到东墙前 → 面向东 → 抬头看气窗 → 读镜子里的符号**。

**流程**：

1. **苏醒**：第一人称低角度，发条小人起身；纸条滑入；读纸条。
2. **照片**：拍立得滑入——照片里太阳门正对走廊，门开着。背面："第一间：爷爷的书房。他总说，太阳落山前要回家。"
3. **探索**：发现四扇门；直接看门看不到符号；抬头发现门上有气窗。
4. **第一次看镜子**：走到东墙前、面向东、看气窗——镜子里是"当前正对东墙那扇门"的符号。第一扇是月亮。
5. **发现规律**：气窗始终映出"正对面那扇门"——但四扇门的符号是固定的，玩家要靠**逐个走近、抬头、读镜子**，把四个符号都记下来。
6. **找到太阳门**：其中一扇门（第三扇）映出太阳——这是真门。
7. **转方向看光**：但太阳门锁着；转身走回书桌，发现**夕阳正好扫过书架中段的书脊**，烫金字显形："日入门，可归"。
8. **拿钥匙**：书桌抽屉锁着；走到留声机前，转动铜喇叭，掉出一把小钥匙。
9. **开抽屉**：拿到太阳门的钥匙 + 一张老照片（爷爷站在同一扇窗前）。
10. **开门**：走到第三扇门前，按 E 开门，离开。

**观察点**：气窗和黄铜镜 = "看到门的外侧"；转身 = 换一个方向。

**为什么转身是必要的**：
- 气窗只在正对面才看得见 → 必须走到对的位置和朝向
- 书脊的烫金字只在黄昏的斜光下显形 → 必须站在特定方位
- 两者都是"站对地方、面朝对方向"才成立，**不是"把房间转过去"**

**秘密**：抬头看气窗时，如果刚好背对西窗，光线会在镜子里形成一道细缝，露出一行小字："吾儿若见此书，当知吾已归家。"

**时长**：5–7 分钟。**最少转身次数**：4–6 次。

### 7.3 第 2 关：卧室「三把锁」

**目标**：打开衣柜后的暗门，拿到微缩房子模型。

**房间**：9.0×6.0×4.4 m。北墙大衣柜（门内嵌穿衣镜）、五斗橱；中央白漆铁艺床；西北梳妆台；东北缝纫机；西墙偏北的窗，薄纱窗帘；东墙一扇门（走不通）。

**核心机制：靠"转身 + 光路"找到床底**

- 太阳几乎贴地，橙红斜光从西窗水平射进来。
- 光先照到**衣柜门内侧的穿衣镜**，再折向床底。
- 但镜子在衣柜门内，**只有站在床这一侧、面向衣柜，才能看到镜子里的反射光路**；如果站在衣柜旁侧看，镜子只是一块反光的玻璃，看不出光路。
- 玩家要在"能看到光路的角度"和"能看到床底的角度"之间来回走。

**三把锁**：

| 锁 | 位置 | 怎么开 |
|---|---|---|
| **锁 A 链条** | 床头 | 走近床头，按 E 拉链条（第一人称近距离交互） |
| **锁 B 符号盘** | 衣柜门内侧 | 面向衣柜、退后一步，看到镜子里映出的三符号顺序；走到密码盘输入 |
| **锁 C 光路** | 床底 | 站在床这一侧、面向衣柜，看到光经镜子折到床底；此时床底亮起，露出铁皮盒 |

**流程**：

1. **进入**：第一人称进卧室；比书房更亮；窗帘透光。
2. **照片**：拍立得在床上：照片里床底有一块光；背面："第二间：妈妈的卧室。她小时候，总把秘密藏在衣柜上面。"
3. **探索**：床、衣柜、五斗橱、梳妆台、缝纫机、录音机；发现月光/夕阳从窗进来。
4. **拉链条**：走到床头，按 E 拉链条，锁 A 开。
5. **找光路**：走到床这一侧，面向衣柜——看到光经柜门里的镜子折向床底。
6. **床底发光**：床底亮起，露出铁皮饼干盒边缘。
7. **移床**：按 E 推床，露出铁皮盒。
8. **铁皮盒**：打开——一把黄铜钥匙、一颗玻璃弹珠、一张对折的纸片（上面只有一个手写日期）。
9. **读符号**：纸片背面压印着"柜子后面"；转身面向衣柜，镜子里映出三个符号的顺序。
10. **输密码**：走到密码盘（在衣柜侧面），输入三个符号，锁 B 开。
11. **推衣柜**：走到衣柜前按 E 推，露出后面的暗门；用钥匙开锁；进入。

**观察点**：**转身时必须停在"能看见光路"的角度**——这是本关最像"观察解谜"的地方。

**秘密**：录音机按下播放键，会放出八音盒旋律（妈妈小时候的曲子，和第 3 关是同一首）。

**时长**：8–10 分钟。**最少转身次数**：8–10 次。

### 7.4 第 3 关：儿童房「房间里的房间」

**目标**：点亮两盏星星灯，打开封死的门。

**房间**：10.4×7.0×4.8 m。西墙偏北铝合金窗；天花板中央星星灯 + 满顶星星夜光贴；东墙封死的门（钉着木板）；中央矮桌 + **娃娃屋**；东北角玩具箱；北墙小书桌、小书架；西侧小床。

**核心机制：转身 + 娃娃屋转盘**

- 娃娃屋是这间房的微缩复制品，**放在矮桌上**。
- 娃娃屋底座的转盘**必须绕着桌子走到不同侧面才够得着**——转盘的把手每转 90° 会朝向下一个方向，玩家得**绕着桌子走**。
- 娃娃屋的窗和大房间的窗方向相反：大房间窗在西，娃娃屋窗在东。
- 两盏灯：
  - 娃光靠**天光**（黄昏的最后一点橙光）→ 点亮娃娃屋小灯
  - 月靠**月光**（玩家手动拉灯绳让太阳落山后）→ 点亮大星星灯

**三大机关**：

| 机关 | 位置 | 怎么用 |
|---|---|---|
| **娃娃屋转盘** | 矮桌 | 绕桌子走到转盘把手那一侧，按 E 抓住，按 ← → 转 90°；转完把手转到下一侧，得绕过去 |
| **灯绳** | 南墙 | 按 E 拉绳，太阳落山，天光变蓝，月亮上来 |
| **封死的门** | 东墙 | 两灯都亮，木板逐块脱落 |

**流程**：

1. **进入**：第一人称进儿童房；明亮；看到娃娃屋在矮桌上。
2. **照片**：拍立得在床上：娃娃屋、星星亮着；角落里有模糊的影子；背面："第三间：你的房间。"
3. **观察娃娃屋**：绕桌子走一圈——发现娃娃屋和大房间几乎一样，但窗方向相反；发现底座有转盘。
4. **读星图**：贴着娃娃屋的窗往里看（需要站对位置和朝向），看到天花板上的星图："太阳 → 月亮 → 回家"。
5. **认方向**：走到矮桌东侧，把娃娃屋转盘转 180°，让娃娃屋的窗对准大房间的窗。
6. **等天光**：黄昏最后一点橙光从西窗进来，进入娃娃屋，小灯亮起（锁存）。
7. **拉灯绳**：走到南墙，按 E 拉灯绳——太阳落山，天光变蓝，月亮上来。
8. **转月光**：绕桌子走到西侧，把娃娃屋转盘再转 90°，让娃娃屋的镜面对准窗外月光。
9. **大灯亮**：月光进入娃娃屋，反射到天花板的大星星灯上，大灯亮起（锁存）。
10. **开门**：两灯都亮，封死门上的木板一块块脱落；走过去按 E 开门。
11. **结尾**：走出门，画面拉远——这间房也是架子上的一个娃娃屋。

**观察点**：**绕桌子走**——转盘把手在四个方向，必须转身去找。这是"转身"在终章的最终形态。

**秘密**：娃娃屋的抽屉里有一张更小的拍立得，照片里是玩家自己。

**时长**：10–12 分钟。**最少转身次数**：10–14 次。

## 8. 美术方向

### 8.1 视觉风格

- 关键词：微缩模型、旧木头、黄铜、灰尘、暖光、八音盒。
- 材质：胡桃木、黄铜、旧纸、磨砂玻璃、羊毛地毯。
- 色调：暖棕、琥珀、暗绿、奶油白；第三关加入星星的暖黄色。
- 后期：轻移轴模糊、暗角、暖色 LUT、灰尘粒子。
- 参考：Monument Valley 的干净构图 + 《小小梦魇》的微缩比例 + 老式娃娃屋的材质。

### 8.2 角色

- 黄铜发条小人，身高 0.5 米。
- **第一人称主视角下角色模型通常不可见**；模型只用于镜子、结尾演出、记忆馆和宣发图。
- 背后有一把发条钥匙；走路是“咔哒咔哒”的机械步（用脚步声和轻微头部起伏表现）。
- 不需要复杂骨骼动画：身体上下轻微起伏 + 手臂摆动 + 钥匙旋转即可。
- 表情：只有两只发光的小眼睛，用亮度表达情绪。

### 8.3 UI

- 极简：视角指示器、照片卡、交互提示点、暂停菜单。
- 字体：手写体（纸条/照片背面）+ 衬线体（UI）。
- 颜色：黄铜金 + 奶油白；提示用暖黄色，不刺眼。
- 加载界面：一句话“正在回忆这间房……” + 一个慢慢转动的发条钥匙。

### 8.4 参考

- Monument Valley：干净构图、换视角改变空间理解的直觉（但我们是转身，不是转房间）。
- The Witness：观察即解谜、无文字教学。
- HAMSTERMIND：观察机关的节奏、可爱角色、提示系统的反面教材。
- HAMSTERMIND：旋转机关和清晰的空间读图。
- Monument Valley：用旋转改变空间关系的直觉。
- 《小小梦魇》：微缩比例带来的压迫/温暖混合感。

### 9.3 运行时架构

**双层房间结构（关键决策）**：

- **可玩层（Mesh 壳）**：手搭的 9.6×6.4×4.6 / 9.0×6.0×4.4 / 10.4×7.0×4.8 矩形房间壳，包含墙体、门洞、地板、碰撞体和剖切面。这一层保证关卡可旋转、可通关、几何精确。
- **视觉层（3DGS 皮肤）**：SpatialGen 生成的**空房间壳**作为视觉皮肤贴在 Mesh 壳内部；如果生成房间的几何与壳不匹配，用裁切、遮罩、局部替换处理。3DGS 不承担碰撞。带家具的生成结果只用于记忆馆/窗外背景。
- **道具层（Lux3D GLB）**：所有关键道具用 Lux3D 生成，放在壳内，承担交互和视觉细节。
- 这样即使 SpatialGen 无法精确控制房间几何，也不影响关卡可玩性；同时 Aholo 的使用仍然是核心：3 个房间皮肤由 SpatialGen 生成、全部关键道具由 Lux3D 生成、第三关娃娃屋由 Lux3D 生成。

```text
LevelRoot (Object3D)
├── RoomShell (Mesh, 可玩层 + 碰撞)
├── RoomSplat (Splat, 视觉皮肤)
├── Props (Group)
│   ├── FixedProps (Drawable)
│   └── MechanismProps (Drawable)
├── Lights
└── Colliders
```

- **不做真实物理模拟**：房间只做左右 90° 旋转；家具固定在房间内，不产生相对运动。状态只需记录“朝向 + 机关 flags”。
- 每关一个 JSON 状态表（见 5.5）。
- 角色移动：当前地板平面 + 射线检测；台阶用预定义的 ramp/step 区域；不做跳跃。
- 相机：纯第一人称。eye height 1.4 m、FOV 72°、鼠标环视（±60°/±45°）；按 ← → 人物原地转身 90°（0.45s）。房间静态，不旋转。
- 光照：3DGS 的烘焙光会跟着房间转；关键光路用独立的体积光/发光材质表现，不依赖实时阴影。
- UI：HTML overlay，绝对定位在 canvas 上。

**镜面实现（第 1 关核心）**：

- 镜子的玩法职责只有一件：**显示“当前转到 N 的那扇门”的外侧符号**。它不需要反射整个房间。
- 默认方案：**小镜面相机**——在走廊里放一台低分辨率相机（512×512），只渲染“门 + 走廊”这一层，不渲染整个 3DGS 房间；房间静止时降到 15fps 更新。成本低，但反射是真实的。**（用户已确认）**
- 兜底方案：**4 张符号贴图 + 反光/视差 shader**——按当前朝向切换对应符号，保留镜面高光和轻微视差，看起来像镜子。**（灰盒先用此方案）**
- 禁止方案：静态贴图不随旋转变化（会直接破坏谜题）。
- M1 灰盒先用兜底方案验证逻辑，M3 再升级到小镜面相机。

### 9.4 性能目标

- 目标设备：2020 年后 MacBook / Windows 笔记本，Chrome/Edge 最新版。
- 分辨率：1440×900 或 1920×1080。
- 帧率：稳定 60fps（最低 30fps 可接受）。
- 首屏加载：< 8 秒（第 1 关）；后续关卡预加载。
- 内存：< 1.5GB。
- 3DGS 使用 LOD/SPZ 压缩，单房间 < 150MB。

### 9.5 音频与素材版权

- 音效优先使用 CC0 / 免版权素材库，或使用 Web Audio 合成（齿轮、木头、金属）。
- 所有第三方素材记录来源和许可证，写进项目报告。
- 音乐小样自录或使用授权素材；不直接使用商业游戏 OST。
- 字体使用开源字体（如思源宋体 / 霞鹜文楷），确认商用许可。


### 9.6 技术假设与依赖

- 团队已报名黑客松，**Lux3D 与 SpatialGen 账号可用**；生成为**网页端手动操作**，没有 API 并发。
- 因生成是手动流程，**资产生成从 Day 1 就开始**，不等灰盒完成；美工负责批量生成、筛选、导出。
- SpatialGen 输出 3DGS 格式（PLY / SPZ）；Lux3D 输出 GLB（网格 + PBR 材质）。
- 3DGS 资产使用 `@manycore/aholo-splat-transform` 做 LOD / SPZ 压缩。
- 目标浏览器需支持 WebGL2；Safari 不作为主要目标。
- 部署为静态站点，不依赖后端服务；所有生成在开发期完成，运行时不调用生成 API。
- 若 SpatialGen 无法直接产出“可旋转的封闭房间”，使用「手搭 Mesh 壳 + 3DGS 视觉皮肤」方案（见 9.3）。
- 生成的房间/道具默认可用于公开展示与小红书发布；如平台有额外限制，在项目报告中注明。

### 9.7 技术验证清单（第 1 周必须做）

1. `@manycore/aholo-viewer` 能否同时渲染 Mesh + Splat，并支持父节点整体旋转？
2. SpatialGen 生成的房间能否裁成 7.5×4.9×4.2 的可旋转矩形房间？边缘是否穿帮？
3. 第一人称相机在转身时，Aholo 生成的 3DGS 房间是否有可接受的光照稳定性？
4. 普通笔记本上的加载时间、显存占用、帧率是多少？
5. 角色碰撞和台阶在旋转后的房间里是否正常？

### 9.8 降级方案

| 风险 | 降级方案 |
|---|---|
| SpatialGen 房间不适合旋转 | 用 Lux3D 道具 + 手搭房间壳（简单几何 + PBR 材质） |
| 3DGS 加载太慢 | 只保留 2 个房间预加载；第 3 关用 Mesh 房间 |
| Aholo Viewer 物理不好用 | 自己写简单的平面碰撞 + 射线检测 |
| 时间不够做结尾实时演出 | 用预渲染短片替代实时结尾 |
| 时间不够做记忆馆 | 砍掉拍照，只保留自由旋转展示 |

### 9.9 开发调试工具

- 调试面板（F1）：显示当前朝向节点 id（如 `O2`）、可旋转边、碰撞体线框、角色坐标、当前地板面。
- 关卡热重载：修改 JSON 后按 F5 重载当前关，不重启游戏。
- 状态跳转：输入朝向节点 id，直接跳到该状态，方便测试每个朝向的线索。
- 一键截图：P 键截图到剪贴板/本地，用于项目报告的过程记录。
- 音效调试：列出所有音效触发点，点击试听。

### 9.10 项目报告的技术栈展示

项目报告里单独做一页“Aholo 使用链路”：

1. 每关的 prompt 原文。
2. SpatialGen 生成结果截图（原始 + 游戏内）。
3. Lux3D 道具生成截图（原图 → 3D 模型 → 游戏内）。
4. 第三关娃娃屋：房间照片 → image-to-3D → 游戏内娃娃屋。
5. 技术栈图：SpatialGen → Lux3D → Aholo Viewer → 游戏。
