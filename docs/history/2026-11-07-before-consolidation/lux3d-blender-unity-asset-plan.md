# 《转间》三关资产生产分工：Lux3D + Blender + Unity

日期：2026-11-05  
状态：供用户确认的生产建议；尚未调用 Lux3D 付费生成，也未创建或迁移 Unity 工程。  
依据：最新欧式三关场景及多视角参考图。旧设计中的网页/SpatialGen 管线不作为本方案前提。

## 1. 核心结论

Lux3D 做有辨识度的复杂外观，Blender 做尺寸、结构和可动件，Unity 做材质最终效果、交互状态和运行时表现。判断单位是“部件”，不是整件家具。

- **L，绿色**：适合单体生成外观网格，之后仍需 Blender 检查。适用于静态玩偶、软包椅、书包、装饰地球仪等。
- **H，橙色**：混合制作。Lux3D 只负责标明的外观/雕饰；Blender 重建内腔、轴、铰链、运动件、支撑和安装尺寸。
- **B**：Blender 直接搭建。建筑、简单家具、重复构件、精密机关和必须与关卡对应的几何。
- **U**：Unity 实现。镜面渲染、光照、发光状态、动画驱动、碰撞、拾取与谜题逻辑；这些不是生成一个模型就会出现的功能。

这是本项目的效率判断，不是对工具能力的绝对限制。官方已有拆件、关节动画等能力；网页账号是否开放、输出是否满足我们的精度，仍需样件验证。不能将“可拆件”理解为自动得到正确的抽屉内腔、铰链和运动轴。[官方能力概览](https://labs.aholo.ai/api-docs/en/intro)

### 何时值得生成

同时满足以下条件时优先 Lux3D：
1. 轮廓、软包、雕饰或材质较复杂，手搭确实耗时。
2. 能准备清楚的单物体参考，而不是只有被遮住的一小角。
3. 允许背面细节与参考略有差别，不影响光路或机关配合。
4. 生成后清理成本预计低于从零制作；先用样件验证，不承诺节省百分比。

简单箱体、平板、圆盘、细杆、文字图案通常直接建更快。可动家具越重要，越应先建结构。

| S07 | 书柜冠部雕花 | H，可选 | 只取植物雕饰/冠部，做可复用装饰模块 | 柜体、层板、门板、标准书本B；谜题书脊单独网格/贴图，不能生成整面书墙后再找文字 |
| S08 | 壁炉上方镜框 | H，可选 | 只生成外框曲线和叶饰 | 镜面是规则平面，Unity单独渲染。此装饰镜与门外观察镜是两个对象，不混淆 |
| S09 | 花瓶/静态花束 | L，装饰批 | 有机花形与陶瓷外观；可跨关复用 | 花束细枝可能粘连；可拆成花瓶网格＋简化花簇/贴片。不是首批通关必需资产 |

**直接 Blender：**
- 四扇门共用一个标准门模型，复制四次；门框、门洞、气窗、玻璃、门把与门轴独立，贴花区留出。
- 走廊、对面高位镜的安装架、镜面平面及门外四符号牌。符号用准确的图形贴图或简单几何。
- 壁炉、连续烟道、墙厚、窗洞、木护墙板、地板、天花板。重复轮廓用模块/曲线处理。
- 书柜直线结构、关键书本、钥匙、信纸、照片卡、地毯平面。照片、文字、图案走2D贴图。
- 基础窗框、铅条/格条精确搭建；彩玻璃图案另做贴图或有限色块，不生成整面窗墙。

**先验证再精做：** 从室内眼高通过气窗能否读到对应门的外侧符号；是否一眼看到全部符号；第三扇门能否在走廊侧正常开启。图中镜面示意不证明光学成立。书脊观察也需确定位置和字高。

**直接 Blender：**
- 五斗橱、床头柜等简单箱体；装饰把手复用，若不打开抽屉就不为其制作内腔。
- 镜门、实际镜面、暗门、普通入口、滑轨与衣柜滑动行程；不要生成“带暗门的一整面衣柜墙”。
- 三槽符号盘的独立转轮/按钮、太阳月亮星星标记；链条环、锚点、解锁扣、钥匙、玻璃弹珠。
- 薄窗帘/被面/蕾丝先用可控薄面与贴图，不因褶皱多就默认把整床生成成一个重网格。
- 铁皮盒的纸片、日期与照片均为2D制作。地毯平面与纹理单独做。

**验证重点：** 固定西窗光经镜子到床底的方向；符号顺序的实际物体来源尚未定稿；衣柜侧滑后暗门至少露出通行宽度，且不撞缝纫机；先关镜门再滑柜是否需要作为操作规则。后者是待灰盒决定的建议，不是已确认玩法。

## 5. 第三关：娃娃屋儿童房

源图：[主视角](../concepts/room3-childroom-european-v2.png)、[全面貌](../concepts/room3-childroom-multiview-v3.png)。

| 编号 | 对象 | 建议 | Lux3D范围与理由 | Blender / Unity 必做 |
|---|---|---|---|---|
| C01 | 兔子玩偶 | L，首批 | 有机形体、缝线和软布外观，适合单体生成 | 静态玩偶，不承诺可摆动骨骼；清理耳朵、脚部与接缝 |
| C02 | 书包 | L | 软包轮廓、口袋、布料外观 | 背面/肩带需补全；不互动时不制作拉链内部 |
| C03 | 地球仪 | L，复用S05 | 同一家族沿用同件物品有叙事价值 | 缩放/换材质，不再生成 |
| C04 | 盆栽 | L，装饰批 | 静态叶簇和花盆 | 叶片粘连、过厚检查；动态风摆另做，不当作生成自带功能 |
| C05 | 花瓶花束 | L，复用S09/B09 | 家族装饰复用 | 调花色即可；密集花束可简化 |
| C06 | 床头灯外观 | H，可选 | 灯座有雕饰可生成；图中普通圆锥灯罩很简单 | 灯罩直接B即可，灯体与发光分开；普通床头灯不是两盏谜题星灯 |
| C07 | 叶形把手 | H，共享样件 | 精致装饰小件可试一个，再复用到家具 | 安装面、孔距和尺寸B校准；轮廓简单时直接B曲线/镜像更省；不必每扇抽屉生成 |

**本关最重要的结论：娃娃屋主体用 Blender，内部小道具复用。**

1. 完成大房间的主模型后，以同一份布局数据/集合制作娃娃屋内饰；缩放的是清理后的模型副本，不是重新让AI猜一次房间。
2. 减少微缩模型细节与材质数量，按最终画面可见度保留形体，不原封不动复制全部高模、灯光、碰撞和脚本。
3. 窗洞方向映射、屋顶、烟囱、小镜面支架、转盘、底座、把手、四档定位、暗抽屉必须B；转盘把手随转动父节点，底座和桌子固定。
4. 大/小星灯共用一套B几何，再独立缩放与控制自发光。规则星形很简单，关键是两个灯的状态不能混。
5. 星图、奖状、夜光贴、照片使用准确2D图案；书架、床、儿童桌椅、玩具箱、活动桌、圆盘直接B，叶饰复用C07。
6. 灯绳用曲线、拉手旋转体，出口木闩、锁舌与双状态灯B；Unity维护日夜、小灯锁存、大灯锁存和门锁状态。
7. 参考图的正面剖开、掀开屋顶是展示手法。如果玩法依赖小窗“接光/挡光”，必须重新设计可玩壳体/挡板，不能将四面敞开的展示模型直接用作光学机关。

Lux3D 可以另外生成一个展示用娃娃屋样件，作为比赛创作探索记录；但这不是当前建议的可玩核心资产，也不在本次生成优先队列中。这样保留AI生成家具在两层世界里的实际使用，不以牺牲空间对应换展示效果。

## 6. 共用B与U资产

| 类别 | Blender交付 | Unity负责 |
|---|---|---|
| 房间壳/走廊 | 墙厚、地面、门窗开口、踢脚线、天花、烟道，按统一实际尺寸 | 场景摆放、遮挡、碰撞层、玩家移动范围 |
| 门/气窗 | 标准化门扇、门框、玻璃、铰链轴；4门实例复用 | 门锁条件、动画、进入下一关 |
| 镜子 | 独立镜框和规则平面，法线方向清楚 | 选择能显示关键物体的镜面渲染方案；仅高金属度/高光或普通反射探针不算完成谜题镜像 |
| 抽屉/盒盖 | 有厚度的分离部件、真实开口与内腔、运动轴 | 拾取、开合、交互距离、状态 |
| 光路/昼夜 | 必要的发光面、遮光挡板、图形网格 | 固定光源、可视化光束、日夜切换、光照/灯态；不把“看到了光”写成“光才存在” |
| 布料/玻璃/地毯 | 控制网格与UV，彩玻璃/花纹独立贴图 | 透明/裁切、自发光、双面需要时启用、阴影检查 |

| 键/符号/文字 | 简单几何、贴图、准确字体图形 | 对应ID、正确顺序、物品状态 |

## 7. 实际生产步骤

### A. 先灰盒，不先批量生成整套家具

在 Blender/Unity 中先用基础几何验证三条关键链：
- 第一关：眼高 → 气窗 → 镜面 → 门外牌；书架线索位置；出口开门净空。
- 第二关：窗/镜/床底；推床行程；滑柜与暗门；符号来源。
- 第三关：绕桌四侧 → 单把手随转盘移动 → 日光锁存 → 拉绳入夜 → 月光锁存 → 开门。

图片中的尺寸与旧文档不完全一致，制作前以统一灰盒确认。不能直接按不同生成视图分别量图搭建。

### B. Lux3D输入准备

官方建议单主体、完整轮廓、干净背景和均匀光照；严重遮挡/反光不利稳定生成。[官方操作说明](https://aholo.featurebase.app/en/help/articles/1087651-lux3d-website-navigation-homepage-and-creation-space)

因此：
- 三张标注图只供选资产，**不要把标注图或整张十宫格直接投入单物体生成**。
- 从已选对象另做中性背景单体参考，去掉夕阳阴影、发光晕、文字标注和旁边家具；被挡住的背面需要补足设计。
- 多视角必须来自同一个明确对象。现有全面貌图已记录桌椅/门扇等一致性误差，不能直接作为精确一致的多视角输入。
- 选择最终Mesh/PBR产物；快速3DGS预览不等于可拆动画网格。格式和模型选项以当前账号任务返回为准。
- 先测试S01或S03加C01两个不同类型样件，看实际清理成本，再决定大批量生成。S01难度较高，适合验证关键道具边界；S03更适合快速验证美术与材质链路。

### C. Blender整理

- 检查尺寸、底面、背面、孔洞、薄杆、法线和重复面；固定比例后再设原点。
- H部件与B结构分开命名，避免假分件：隐藏表面贴缝不等于抽屉真的能拉开。
- 需要开合的部件重建内侧，原点设在实际铰链；滑动件记录局部运动轴。
- 反光玻璃、透明灯罩、金属、布料独立材质，不把玻璃反射中的窗景留在颜色贴图里。
- 根据目标设备优化网格、贴图和材质槽。尚未确定Unity版本、渲染管线、目标设备，不把面数/贴图大小写成硬验收指标。
- LOD和碰撞按实际性能需求补充；一般家具使用简单碰撞组合，不让高密度视觉网格承担所有碰撞。

### D. Unity交付

建议显式导出FBX和独立纹理，经导入测试后制作Prefab；不要依赖团队每个人本机的隐式.blend导入。Unity官方以FBX为主要模型导入格式。[Unity模型导入](https://docs.unity.com/en-us/engine/6000.6/manual/assets-and-media/asset-types/models/importing/importing-model-files)

- Lux3D若提供GLB，可先到Blender整理再导出FBX。若选择Unity直接读GLB，则须另核对所用导入包、版本和材质支持，不当成默认依赖。
- 渲染管线尚未确定。若用URP，核对Smoothness来源与Alpha通道、金属度、AO、法线色彩空间、透明和自发光；需要由Roughness转换时按贴图含义处理，不盲目把所有灰度图反相。[URP Lit](https://docs.unity.cn/Packages/com.unity.render-pipelines.universal@17.0/manual/lit-shader.html)
- 光照与材质在Unity中最终验收；发光外观和照亮环境是分别检查的事项。
- 父节点管交互，子节点管可动网格；把碰撞、拾取点、音源、灯光和逻辑与生成视觉网格分开。
- 命名示例：S01_Gramophone_Visual、S01_HornPivot、S01_KeyCompartment；B05_WardrobeRoot、B05_LeftDoorPivot、B05_Mirror；C_TurntableRoot、C_Crank、C_FixedBase。只是交付约定建议，不是现有工程代码。

## 8. 用户确认后的生成队列

**先确认这8类是否保留，避免一次性生成全部图标：**
1. S01留声机外观（H，关键道具）。
2. S03书桌椅（L，材质/造型样件）。
3. S06花瓣灯外观（H，后续B08复用）。
4. S02书桌雕腿/外观（H，关键抽屉另做）。
5. B01缝纫机机头（H，场景识别）。
6. B02录音机壳（H，情感交互）。
7. C01兔子玩偶（L，软质样件）。
8. C02书包（L，童年氛围）。

若目标是最快做可玩版本，只优先做留声机和录音机等核心视觉件，其他先用B简模。橙色候选中的冠部、把手、杯子、铁皮盒花纹都允许改为手工方案，不因“已标注”而必须消耗生成次数。

三张图合计26个编号，是26个确认位置/制作条目，**不是26次生成任务或26件独立新模型**。地球仪、花瓶、灯具与叶饰需要复用；被标成H的家具也可能拆成多份输入，任务数以确认后拆件为准。

## 9. 验收与证据

- L：外观符合目标、背面完整、尺寸可用、材质可重建、导入Unity正常。
- H：除L外，必须验证实际开合/滑动，关键道具能放入并取出，无穿模、轴心正确。
- B/U：以可玩逻辑验证门、光路、碰撞和状态，不以AI参考图的示意箭头作为通过证据。
- 保存单体参考、生成参数/版本、原始下载文件、Blender清理文件、Unity截图及资产来源记录，展示AI实际参与的部分。
